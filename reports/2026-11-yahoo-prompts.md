# HENGE の本番のお題での Yahoo API との比較（2026-11）

数字を含まない一般の文での比較（PR #51 の `reports/2026-11-yahoo-numeral-free.md`）では、本番構成と Yahoo に有意差が出なかった。HENGE が配信するのは一般の文ではなく生成したお題なので、本番のお題で測り直した。

結果として、本番のお題では本番構成が Yahoo を上回った。読みが割れた136文のうち、本番構成だけが正しい文は94、Yahoo だけが正しい文は19だった。

## 比べた構成

| 構成 | 中身 |
|---|---|
| 本番構成 | v3.2 辞書 ＋ main の `user-lex.csv`（PR #55 のマージ後、263行）。HENGE の読み Worker と同じ `readingOf` で組み立てる |
| 辞書のみ | v3.2 辞書。user-lex を重ねない |
| Yahoo | Yahoo! ふりがな API V2（`grade=1`）に1文ずつ送る。計測は 2026-11-07 |

## お題

本番の D1 の `prompts` にある5,156件を使った。同じ文を1つにまとめると4,512文になる。内訳は単語1,035、短文3,362、長文115である。

## 結果

両者の読みが同じ文は4,375で、全体の97%だった。却下は本番構成が0文、Yahoo が1文（「しんどい一日だったけど頑張った」の 一 を読まなかった）だった。

読みが割れた136文は、抜き出さずに全部を判定した。判定者は Claude（Opus 5.5）1人である。文ごとに無作為に A/B を割り当て、対応表は判定が終わるまで見なかった。1文に誤りが1か所でもあれば、その読みを誤りとした。文ごとの結果は `reports/2026-11-yahoo-prompts-verdicts.tsv` にある。

| 形式 | 文 | 割れた文 | 本番だけ正しい | Yahoo だけ正しい | どちらも可 | どちらも誤り |
|---|---|---|---|---|---|---|
| 単語 | 1,035 | 23 | 15 | 2 | 4 | 2 |
| 短文 | 3,361 | 99 | 70 | 15 | 12 | 2 |
| 長文 | 115 | 14 | 9 | 2 | 1 | 2 |
| 合計 | 4,511 | 136 | 94 | 19 | 17 | 6 |

短文の文数には Yahoo が却下した1文を含めていない。全体での差は本番構成が +1.66pt（95%信頼区間 +1.29〜+2.02）で、信頼区間は0をまたがない。信頼区間は判定した136文を文単位でブートストラップして求めた。

同じ文をまとめずに5,156件で数えると、本番構成だけの誤りは19件、Yahoo だけの誤りは96件だった。

## 読み取れること

- **Yahoo は短い文で熟語を1字ずつに切ることがある。** 雰囲気→きりかこいき、瞬間→まじろぎま、意味→いあじ、質問→しつとい、資金→しかね、協力→きょうちから のような読みが出た。同じ文を送り直しても同じ応答だった。語を単独で送ると、雰囲気、瞬間、質問は正しく読む
- **差の大部分は辞書による。** 本番構成だけが正しい94文のうち88文は、辞書のみでも本番構成と同じ読みだった。user-lex をこのお題に合わせて調整した影響で差が開いたとは言えない
- **一般の文の結果とは矛盾しない。** 一般の文の判定では +1.15pt（−0.24〜+2.55）だった。お題は短く日常語が多いので、結果が違っても不思議ではないが、違いの原因は切り分けていない

## 本番構成に残る誤り

本番構成が誤った25文（本番構成だけの誤り19、どちらも誤り6）の内訳である。

| 分類 | 語 |
|---|---|
| PR #57 で直す | 役者町、城下町、愛情深い、シカの角、コミュニケーション力、空気に入る |
| 文脈で読みが割れる | 辛い（3文）、抱いている、審査に通った、屋台の下、風穴が開く（2文）、市場に通う |
| 語を外す候補 | 福岡国際機場 |
| 今回の比較で初めて見つかった | 交通の便→びん、陰陽→おんみょう、大字→おおあざ、城跡→じょうあと、使い勝手→つかいかって、昔話好き→むかしはなしずき、御用聞き→ごようぎき、手羽先→てはさき、出入り口→でいりくち |

## 注意点

- 判定は1人の判断で、人手の正解データとは性質が違う。役者町や春吉のように以前の点検で見た語もあり、どちらの読みか推測できる場合もあるので、完全なブラインドではない
- 両者が同じ読みで同じように誤る文は数えていない。この比較で分かるのは両者の差で、誤読率そのものではない
- user-lex の一部はこのお題の点検と報告から作ったので、本番構成に有利である。辞書のみの数字は上の「読み取れること」に書いた
- 固有名詞の多い Wikipedia 見出し語で Yahoo が上（PR #51 の報告で −3.70pt）という結果は、この比較では確かめていない
- Yahoo の結果は API 側の更新で変わりうる。お題は増えるので、この数字は計測時点のものである

## 再現

お題の文と読みの出力は、リポジトリに入れない。`reports/2026-11-yahoo-prompts-verdicts.tsv` には、お題の ID、形式、判定、辞書のみの読みがどちらと同じかだけを載せている。`read-engine.ts` と `read-yahoo.py` は PR #51 で入る。Python の証明書でエラーになるときは、`SSL_CERT_FILE` で CA バンドルを指定する。

```sh
cd eval/yahoo-compare
# HENGE の apps/backend で実行して、出力を prompts.json に保存する
# bunx wrangler d1 execute henge-db --remote --json --command "SELECT id,form,text FROM prompts"
python3 -I prompts.py prepare prompts.json work
HENGE_ROOT=/path/to/HENGE bun read-engine.ts /path/to/user-lex.csv work work/prompts.jsonl
YAHOO_APP_ID=... python3 -I read-yahoo.py work/yahoo.cache.jsonl work/prompts.jsonl
python3 -I prompts.py sheet work
python3 -I prompts.py verdicts work 判定.txt ../../reports/2026-11-yahoo-prompts-verdicts.tsv
python3 -I prompts.py tally ../../reports/2026-11-yahoo-prompts-verdicts.tsv
```
