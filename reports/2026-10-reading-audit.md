# 読み誤りの実測と、トリム辞書・ユーザー辞書の調査（2026-10）

HENGE の生成条件に合わせたお題を約120テーマ・860件作り、本番と同じ組み立て（v7800n-slim2 ＋ `user-lex.csv`、
読みは特徴列 index 7）で読んで、期待の読みと照合した。6ラウンドに分けて、毎回新しいテーマで作り直している。

## 結論

- **本番構成の正解率は 72.6%（860件中 624件）。** 誤読のまま配信される件が 213件、UNKNOWN_READING で却下される件が 23件。
  文字誤り率（CER）は 6.62%。長文は 12本中 1本しか全文正しく読めない
- **最大の原因はトリムではなく接続表。** 配布辞書の接続コストは MeCab の接続行列より**全ペアで一様に 5376 低い**
  （4,272本の接続で −5393〜−5361）。トークンが1つ増えるごとに 5376 得をするので、熟語を割った経路が勝つ
  （黒板→くろ+ばん、勝利→がち+りし、水素→みず+そ）。語コストに +5376 を足すだけで 68.4% → 75.3%（ユーザー辞書なし）
- 2番目は**重複除去**。`(表層, 読み)` の先勝ちで同形の別品詞が消え、「回して」「過ぎて」「干して」が 回/かい+して・過/か+ぎて に割れる
- 3番目が**閾値で落ちた頻出語**。言葉・絵・皿・宝・虹・秒・週・変わる・洗っ・鳴く 等が辞書に無い
- これらを直した辞書（`scripts/filter_lex_v3.py`）は **87.1%（CER 1.96%、UNKNOWN_READING 0件）**。同じ接続表に UniDic の
  全語彙を載せた辞書（86.6%）と同等で、**wasm メモリは 84.1MB → 76.2MB、zst は 6.92MB → 6.12MB と小さくなる**
- **ユーザー辞書 751行のうち 106行は今すぐ消してよい**（実→ミ で 実力→みりょく、場→バ で 劇場→げきば、日→ヒ で 前日→まえひ 等。
  消しても回帰テストは期待値の疑わしい2件を除いて通り、正解率はわずかに上がる）。v3 に移すと、さらに 566行が不要になる
- v3 でも残る誤り（約13%）の大半は UniDic 自体の誤り（フルでも同じ）で、連濁・数詞・熟字訓・同形異音が中心。
  ここがユーザー辞書の本来の守備範囲

## 方法

- **コーパス**（`eval/corpus/round1〜6.tsv`）: HENGE の生成プロンプト（`apps/backend/src/generation/prompt.ts`）の条件に合わせ、
  短文（かな8〜18字）677件・単語171件・長文12本を書いた。期待の読みは手で付け、揺れる語は別解を `|` で並べた
  （深々・注ぐ・蛙・塩 等）。round1〜2 で原因を調べ、round3〜6 は新しいテーマでの確認、round5・6 はすべての調整を決めた後のブラインド検証
- **比べた辞書**
  - 本番: Release の `unidic-cwj-v7800n-slim2.dic.zst` ＋ `user-lex.csv`（`scripts/lib/reading.ts` と同じ組み立て）
  - フル: UniDic 3.1.0（MeCab 版 `sys.dic` から語彙を復元。ninjal からの取得がこの環境では通らなかったため、
    unidic-py の配布物を使った）。lid/rid の空間は配布辞書と一致した（接続コストの差が全ペアで定数になることで確認）
  - 改善案の辞書は、復元した 3.1.0 の語彙を**配布辞書の接続表にそのまま載せ替えて**作った（model.def が無くても検証できるように）
- **計測**: `bun eval/run-eval.ts`（本ディレクトリに同梱）。wasm メモリは `vendor/reading-wasm-pkg` の `Reader.from_zstd` 前後の
  `memory.buffer` の差

## トリム辞書の問題点

### 1. 接続コストが一様に 5376 低い（最大の原因）

配布辞書でトークン列の累積コストから逆算した接続コストを、UniDic（MeCab 版）の接続行列と比べると、
BOS 以外の全ペアで差が −5376（±16）だった。BOS からの接続は常に 0。

- トークンが1つ増えるごとに経路が 5376 得をするので、**辞書にある熟語より、1字語や接尾辞に割った経路が勝つ**。
  本番の誤り 236件のうち 104件は、フル辞書より多くのトークンに割っている
- ユーザー辞書の `-20000`（熟語の強制勝ち）は、この偏りを力ずくで打ち消していた。牛乳・職人・大会・理解・開発・解決・実現・
  歴史・自然 のような基本語が並んでいるのはそのため（258行が該当。v3 では不要）
- SUMMARY.md の「trim と full は互角」は、full も同じ接続表で作っていたため、両方が同じ偏りを持っていた
- 原因の推定: `vibrato::mecab::generate_bigram_info` が model.def の重みの一部（全ペアに共通の項）を落としている。
  model.def が手元に無く、ここは確かめていない。**直し方は語コストに足すだけでよい**: 各トークンは入ってくる接続をちょうど1本持つので、
  全語（システム辞書・未知語・ユーザー辞書）の語コストに +5376 を足せば、BOS 以外の接続は MeCab と同じになる
- BOS/EOS が 0 になる近似の影響は小さかった（MeCab と同じ接続行列を使った辞書は 85.8% で、むしろ低い）

### 2. 重複除去が同形の別品詞を消している

`(表層, 読み)` の先勝ちで重複除去しているため、読みが同じで品詞（lid/rid）が違う行が消える。先に名詞・接尾辞の行があると動詞の行が消え、
**連用形が名詞と同形の動詞**（願い・回し・干し・洗い・巻き・過ぎ・継ぎ・跳ね）がまとめて落ちる。「お願いします」が お+願/がん+いし+ます になるのもこれ。
`(表層, lid, rid, 読み)` で最小コストを残せば、Viterbi の結果を変えずに重複だけを除ける（約5.9万行増える）。

### 3. トリムしすぎている部分

- 品詞別のコストは**品詞の中での相対値**で、頻度の目安としては粗い。普通名詞 6200・動詞 7800・形容詞 7200 の閾値で、
  言葉(6848)・絵(6776)・皿(6293)・宝(6284)・虹(6305)・秒・週・来週・製品・部長、変わる・得る・泣く・鳴く(9087)・洗っ(7885)・下がら(7832)、
  楽し・大き・悔し(7209)・恥ずかし が落ちている
- wordfreq の頻度で見ると、**漢字を含む頻出語（zipf ≥ 4.0）4,683語のうち 108語（2.3%）が配布辞書に無い**。
  zipf ≥ 5.0 でも 言葉・号・楽し・組・絵・秒・笑 が無い。ユーザー辞書の 言葉・楽し・大き・変わる・当日・合っ はこの穴埋め
- v3 は「表層の頻度が zipf ≥ 2.0 なら、その表層の最小コスト + 3000 までの行を残す」を足した。頻出語の欠落は 0語になり、
  UNKNOWN_READING も 0件になった。これ以上語彙を増やしても（行数 72万・wasm 88MB まで試した）正解率は上がらなかった

### 4. 逆にトリムしてよい・すべきもの

- **カタカナだけの名詞（読み＝表層）約8.8万行**: 未知語になっても表層がそのまま読みになるので、読みは変わらない（860件で差なし。
  ビル・メダル・ラベンダー 等は未知語として正しく読めた）。メモリを最も減らせる
- **濁音形が基本形に常に勝つ組（298組）**: 表層・lid・rid が同じで濁音形の方が安いので、文脈によらず濁音形が出る。
  川→がわ、蛸→だこ、小屋→ごや、灰→ばい、戸→ど、合戦→がっせん、鱈→だら、鰹→がつお、殺し→ごろし、沿い→ぞい。
  単純に消すと 小春日和・犬小屋・王手飛車取り が壊れるので、v3 は濁音形の lid を接尾辞のもの（10234）に替えて +1500 した。
  名詞の後では濁音形、文頭・助詞の後では基本形になる（文の途中の「。川の」は まだ がわ になる）
- **稀な読みが既定になっている語**（UniDic の値のまま。消すか、同じ lid/rid でユーザー辞書から差し替える候補）:
  樽→そん、土器→かわらけ、柴犬→しばけん、搾る→しめる、転生→てんしょう、同人→どうにん、杏仁→きょうにん、白熊→はぐま、
  鶏肉→けいにく、塵→ごみ、千里→ちさと、千秋→ちあき（千秋楽）、一寸→ちょっと（一寸法師）、明後日→みょうごにち、銀杏→ぎんなん
- **送り仮名を省いた1字の語**（洗→あらい、干→ほし、跳→とべ、癒→いえ、獲→え、試→み、挽→ひき、継→つぎ、悔→かい）:
  配布辞書では動詞の活用形が欠けているせいでこれが選ばれ、「洗って→あらいって」になっていた。v3 では活用形が入るので選ばれなくなる
  （消す実験もしたが、v3 の上では差が出なかった）

### 5. メモリの非単調な跳ね

特徴列が `名,*,*,*,*,*,*,カナ,*` のままだと、wasm メモリが行数に対して**非単調に約17MB跳ねる**
（同じ語彙を先頭から切って、53.5万行 100.5MB・53.9万行 84.0MB・54.0万行 101.0MB）。配布辞書（53.98万行・84.1MB）はたまたま低い側にいる。
特徴列を `,,,,,,,カナ,` に縮めると 74.5〜76.2MB（52万〜54.5万行）でなだらかに伸び、跳ねは出なかった。
HENGE は index 7 しか見ない（`apps/reading/src/reading.ts`）ので、縮めても読みは変わらない。

  一→イチ（一体→いちたい・一匹→いちぴき）、方→カタ（方位磁石→かたい）、試→タメ（試験管・試作品）、使→ツカ（遣唐使）、

- **壊れた活用**: 追っます・追ったい・追っない・拾っます・入っます 等 9行
- その他: 蒲焼→カバヤキ（-20000。蒲焼き→かばやき+き）、春日→カスガ（小春日和→しょうかすがわ）、連れ→ヅレ、重複 7行

この106行を消した `user-lex.csv` で、860件は 624 → 626件、CER 6.62% → 6.45%。`bun test` は 83件中 81件が通り、
落ちる2件は下の「回帰テストの期待値」に挙げたもの。

### 仕組みの問題

- **巻き込み検査（#19）は語境界をまたぐ巻き込みを拾えない。** 検査は「その表層を含む辞書の1語」を解析し直すだけなので、
  `書に` が「司書＋に」を、`川の` が「柳川＋の」を割ることは見えない。頻出語の末尾＋助詞（司書に・柳川の）も解析し直す必要がある
  （調査では wordfreq の zipf ≥ 3.5 の語で、各行の表層の前半で終わる語＋後半の仮名、を作って読み比べた）
- 1字の裸登録は #19 で止まるはずだが、検査の導入前に入った行（実・場・日・一）がそのまま残っている。`bun scripts/check-collateral.ts --all` の棚卸しが要る
- `-20000` 以下の強制勝ちが多い（477行）。熟語を割る偏りに勝たせるための値で、v3 ではその多くが要らない。
  残す行も文脈によらず必ず勝つので、境界をまたぐ巻き込みはこの値の行ほど起きやすい

### 回帰テストの期待値

`scripts/regression.test.ts` の次の期待値は、一般的な読みと違う:

- 試合中に怪我をした → しあい**じゅう**（「〜の最中」の 中 は ちゅう が普通。じゅう は 一日中・世界中 の「〜の間ずっと」）
- 授業中に寝る → じゅぎょう**じゅう**（同上）
- 手に入った本 → てに**いった**（標準は てにはいった）
- 差し入る季節 → さしいる（「差し入る」自体がほぼ使われない）

   （`bun eval/run-eval.ts --lex-shift 5376` で効果を見られる）。調査は 3.1.0 の語彙で行ったので、3.1.1 で作り直したら
   `eval/run-eval.ts` と wasm メモリを測り直すこと。workerd の実 isolate でのロード時ピークも確かめる
3. v3 に移したら、ユーザー辞書の「v3 では不要」566行を消し、残りを回帰テストで確かめる。整理後（79行）の実測は 87.8%
4. 回帰テストの期待値（試合中・授業中・手に入った本・差し入る）を見直す
5. 巻き込み検査に「頻出語の末尾＋後ろの仮名」の境界版を足す
6. `eval/corpus` を CI で回し、正解率の下限を置く（辞書・ユーザー辞書の変更が全体を下げていないかを見る）

## 再現

```sh
bun scripts/fetch-dict.ts
bun eval/run-eval.ts eval/corpus/*.tsv                 # 本番構成
bun eval/run-eval.ts --no-lex eval/corpus/*.tsv        # 辞書のみ
bun eval/run-eval.ts --show eval/corpus/round6.tsv     # 誤りをトークン列つきで
UNIDIC_DIC_PATH=path/to/v3.dic.zst bun eval/run-eval.ts --lex-shift 5376 eval/corpus/*.tsv
```

件数の小さな差（1〜2件）は期待値の揺れの範囲として読むこと。
