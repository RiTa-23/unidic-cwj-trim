# 数字を含まず現代の語彙に絞った文での Yahoo API との比較（2026-11）

Yahoo! ふりがな API は漢数字に読みを返さない。4者比較（`reports/2026-10-four-way.md`。main には未マージで、`a5472d7` にある）は、その文を却下に数えていた。
そこで、数字を含まない文だけで本番構成と Yahoo を測り直した。今回の版では、user-lex を今の main のものに更新し、青空文庫と Wikipedia 本文を現代の語彙の文に絞り直した。

結果として、一般の文では本番構成と Yahoo はほぼ同等で、本番構成がはっきり上回るとは言えない。人手の正解がある KWDLC では本番構成が有意に上だが、青空文庫では差がなかった。読みが割れた文の判定では、4コーパスの平均が +0.26pt（−0.93〜+1.43）だった。固有名詞の多い Wikipedia 見出し語では Yahoo が有意に上だった。

## 比べた構成

| 構成 | 中身 |
|---|---|
| 本番構成 | v3.2 辞書（`f4775d17…`）＋ `3f87618` の `user-lex.csv`（269行）。HENGE の読み Worker と同じ `readingOf` で組み立てる |
| 辞書のみ | v3.2 辞書。user-lex を重ねない |
| Yahoo | Yahoo! ふりがな API V2（`grade=1`）に1文ずつ送る。計測は 2026-11-07 |

## 文の選び方

コーパスの共通条件は `eval/yahoo-compare/common.py` にある。かな・漢字・句読点・「」だけからなり、漢字を含む8〜200字の文を採った。

数字は広めに除いた。算用数字は文字の条件で落ち、漢数字（一〜九、十、百、千、万、億、兆など）は語の一部でも文ごと落とした。「一緒」「千葉」のような語を含む文も入っていないので、これらの語の読みは今回の数字に表れない。

| コーパス | 候補の文 | 使った文 | 正解の読み |
|---|---|---|---|
| KWDLC（`c6ae49d`） | 10,156 | 10,156（全部） | 人手の形態素情報 |
| 青空文庫（国立国会図書館の振り仮名注釈コーパス） | 80,339 | 10,000 | 点字データから作った振り仮名 |
| livedoor ニュース（`ldcc-20140209`） | 63,274 | 10,000 | なし |
| Wikipedia 本文（2026-11-01 更新のダンプ、分割1・4） | 461,954 | 10,000 | なし |
| Wikipedia 見出し語（別枠） | 30,188 | 3,000 | 見出しの「漢字（よみ）」だけ |

- 青空文庫の振り仮名は点字に合わせて「は」を「わ」、「とうじ」を「とーじ」と書く。かな部分は本文の表記を使い、長音は両者に同じ変換をかけてそろえて採点した
- Wikipedia 本文は1ページ3文までとし、長い記事に偏らないようにした。テンプレートが抜けた行は文が欠けるので捨てた
- Wikipedia 見出し語は、読みが見出しの「よみ」から始まれば正解とした

### 現代の語彙への絞り込み

前回の青空文庫には、古い小説の語彙や言い回しが多く含まれていた。そこで青空文庫と Wikipedia 本文に次の条件を足した。この条件は読みを比べる前に決めた。KWDLC と livedoor には足していない。

- 漢字: `modern-kanji.txt` の2,905字だけを使う文に限った。HENGE の共通語彙のうち出現頻度が高い語（zipf 3.5以上）の漢字である
- 語: 「侍」「奉行」「幕府」「天皇」「明治」のような時代を示す語を含む文を除いた
- 文末: 「じゃ」「ぬ」「けり」「であろう」のような古い言い回しで句点や読点に続く文を除いた
- 青空文庫だけの条件: 1900年以降に生まれた著者が書いた、新字新仮名の作品に限った。時代小説の多い山本周五郎と本庄陸男の作品と、「云」を含む文も除いた

絞り込んだ青空文庫でも、中心は太宰治、坂口安吾、火野葦平のような1930〜60年代の文学である。今の日本語とは書き方に差が残っている。

Wikipedia 見出し語は、前回と同じ候補から抜いているが、抜いた文は前回と同じではない。全体の数字に加えて、上の漢字、語、文末の条件を満たす1,962件の数字も出した。

Yahoo には重複を除いて 43,155文を送った。エラーが返った文は9だった。

## 正解データとの比較

却下は、読みが返らないか、読みに漢字が残った文である。正解率は却下を不正解に数える。

| コーパス | 構成 | 正解率 | 誤読 | 却下 |
|---|---|---|---|---|
| KWDLC | 本番構成 | 88.06% | 1,206 | 7 |
| | 辞書のみ | 83.66% | 1,652 | 7 |
| | Yahoo | 86.30% | 1,390 | 1 |
| 青空文庫 | 本番構成 | 79.60% | 1,992 | 48 |
| | 辞書のみ | 68.87% | 3,065 | 48 |
| | Yahoo | 79.53% | 2,035 | 12 |

| 比較 | KWDLC | 青空文庫 |
|---|---|---|
| 本番構成 − Yahoo | +1.75pt（+1.05〜+2.48） | +0.07pt（−0.87〜+0.89） |
| 辞書のみ − Yahoo | −2.64pt（−3.49〜−1.78） | −10.66pt（−13.88〜−7.95） |

括弧は文書単位のブートストラップによる95%信頼区間である。

青空文庫の辞書のみが低いのは、主に「私」の読みによる。本番構成と辞書のみで読みが変わった1,551文のうち、1,132文が「私」を含む。

Wikipedia 見出し語の結果は次のとおりである。

| 対象 | 件数 | 本番構成 | Yahoo | 差（本番構成 − Yahoo） | 却下（本番構成 / Yahoo） |
|---|---|---|---|---|---|
| 全体 | 3,000 | 73.40% | 76.90% | −3.50pt（−4.97〜−2.03） | 63 / 9 |
| 現代の語彙の文 | 1,962 | 77.17% | 80.33% | −3.16pt（−4.89〜−1.33） | 22 / 0 |

辞書のみの全体の正解率は 72.77% だった。「株式会社」を読みに含めない見出しのように、正解データの揺れも混ざっている。

## 読みが割れた文の判定

両者の読みが同じ文は、正しくても誤りでも正解率の差に影響しない。そこで、どちらかが却下された文を除き、本番構成と Yahoo の読みが割れた文を無作為に抜いて判定した。正解データのないコーパスでも、この方法で差を推定できる。

判定者は Claude（Opus 5.5）1人である。文ごとに無作為に A/B を割り当て、コーパスも混ぜ、対応表と正解データは判定が終わるまで見なかった。1文に誤りが1か所でもあれば、その読みを誤りとした。「等」の など と とう、「明日」の あす と あした のように両方の読みが成り立つものは、どちらも可とした。文ごとの結果は `reports/2026-11-yahoo-verdicts.tsv` にある。

| コーパス | 割れた文 | 判定数 | 本番だけ正しい | Yahoo だけ正しい | どちらも可 | どちらも誤り | 全体での差（95%信頼区間） |
|---|---|---|---|---|---|---|---|
| KWDLC | 1,430 / 10,156 | 150 | 63 | 55 | 25 | 7 | +0.75pt（−1.31〜+2.72） |
| 青空文庫 | 1,987 / 10,000 | 150 | 61 | 56 | 8 | 25 | +0.66pt（−2.25〜+3.44） |
| livedoor | 1,252 / 10,000 | 200 | 88 | 92 | 13 | 7 | −0.25pt（−1.94〜+1.38） |
| Wikipedia 本文 | 2,407 / 10,000 | 200 | 70 | 71 | 22 | 37 | −0.12pt（−2.77〜+2.65） |

どのコーパスでも信頼区間が0をまたぐ。4コーパスの単純平均は +0.26pt（−0.93〜+1.43）で、これも0をまたぐ。

## 読み取れること

- **一般の文では同等と説明するのが実測に合う。** KWDLC の正解データとの比較だけが有意に本番構成の上で、KWDLC は user-lex の調整に使っている。調整に使っていない青空文庫では差がなく、判定でも有意差は出なかった
- **固有名詞では Yahoo が上だった。** 現代の語彙の文に限っても差はほぼ変わらない。本番構成は却下も多いが、却下は誤読を配信しないので安全側の失敗である
- **本番のお題とは結果が違う。** HENGE が配信するお題では、本番構成が有意に上だった（`reports/2026-11-yahoo-prompts.md` の +1.66pt。お題の整理と user-lex の更新のあとに測り直すと +1.89pt、+1.58〜+2.16）。お題は短く日常語が多いが、違いの原因は切り分けていない
- **辞書のみは Yahoo より有意に低い。** 本番構成が Yahoo に並んでいるのは user-lex の効果である
- **前回の数字と比べられるのは KWDLC と livedoor だけである。** KWDLC の正解データとの比較は文が同じなので、+1.56pt から +1.75pt への変化は user-lex の更新による。判定の差は抜いた文が変わるので、KWDLC の −0.76pt から +0.75pt への変化には抜き方の揺れも含まれる。青空文庫と Wikipedia は文の集まりが変わったので、前回の数字とは比べられない

### 判定で見えた誤りの傾向

- 本番構成の誤り: 複合語の連濁と接尾辞（実家暮らし→じっかくらし、スポーツ紙→すぽーつかみ、マンガ好き→まんがすき）、語の切り方（お気に入り→おきにはいり、単行本→たんこうほん）、固有名詞（高野進→たかののすすむ、上岡龍太郎→うえおか）
- Yahoo の誤り: 多義語の選び違い（を行っている→をいっている、当直は辛い→からい、関心のある方→ほう）、語の切り方（時間帯→じかんおび、協力→きょうちから）、固有名詞（小泉成器→こいずみしげき）

### 同じ語で毎回外すもの

4コーパスの本文で、例に挙げた語を含む文を数えた。どんな風 などの14文と を行っ の147文は、本文を読んで「ふう」「おこなう」の意味であることを確かめた。どんな風 などの14文はすべて「〜風に」の形で、本番構成の残りの1文は却下だった。「どんな風が吹く」のように かぜ と読む文もあるので、この語は文脈を見ずには直せない。

| 語 | 含む文 | 本番構成の誤読 | Yahoo の誤読 |
|---|---|---|---|
| お気に入り→おきにはいり | 28 | 26 | 0 |
| どんな風・こんな風・そんな風→かぜ | 14 | 13 | 0 |
| 単行本→たんこうほん など | 9 | 9 | 0 |
| 跨線橋→こせんばし | 5 | 5 | 0 |
| を行っ→をいっ | 147 | 0 | 142 |
| 独女→ひとりおんな | 74 | 0 | 74 |
| 世界中→せかいちゅう | 25 | 0 | 25 |
| 時間帯→じかんおび | 20 | 0 | 20 |

前回の報告で本番構成がすべて誤読していた お母さん と お父さん は、今の user-lex で直っている。今回は お母さん を含む35文のうち1文が却下になっただけで、お父さん を含む36文はすべて おとうさん と読んだ。

## 注意点

- 判定は1人の判断で、人手の正解データとは性質が違う。判定数も150〜200文なので、信頼区間は広い。読みの癖からどちらの読みか推測できる場合もあり、完全なブラインドではない
- KWDLC は dev 側の半分を user-lex の調整に使っている（`reports/2026-10-kwdlc.md`）ので、本番構成に有利である。辞書のみの行が調整の影響の少ない比較になる
- 青空文庫、livedoor、Wikipedia を調整に使った記録は `reports/` にない。ただし、今回の user-lex には お母さん のような前回の判定で見つけた語が入っている。これらのコーパスの文から見つけた語なので、本番構成に少し有利である
- 現代の語彙の条件は機械的なものなので、古い言い回しが残る文も、現代の文なのに除かれた文もある
- 青空文庫の正解率の絶対値は点字由来のノイズの影響を受けていると考えられ、あてにならない
- Wikipedia はダンプ全体ではなく2分割分から採った
- Yahoo の結果は API 側の更新で変わりうる

## 再現

コーパスの文と読みの出力は、リポジトリに入れない（`eval/README.md`）。`reports/2026-11-yahoo-verdicts.tsv` には文の ID と判定だけを載せている。スクリプトは `eval/yahoo-compare/` にある。Python の証明書でエラーになるときは、`SSL_CERT_FILE` で CA バンドルを指定する。

青空文庫の抽出には作品一覧の `list_person_all_extended_utf8.csv` も使う。https://www.aozora.gr.jp/index_pages/list_person_all_extended_utf8.zip から取得して展開する。

```sh
cd eval/yahoo-compare
python3 -I extract-kwdlc.py /path/to/KWDLC . work/kwdlc.jsonl
python3 -I extract-aozora.py /path/to/aozora . work/aozora.jsonl /path/to/list_person_all_extended_utf8.csv   # aozora_dataset を x/ に展開した場所
python3 -I extract-livedoor.py /path/to/livedoor . work/livedoor.jsonl    # ldcc を x/ に展開した場所
python3 -I extract-wikipedia.py work/wikipedia.jsonl . p1.xml.bz2 p4.xml.bz2
HENGE_ROOT=/path/to/HENGE bun read-engine.ts /path/to/user-lex.csv work work/kwdlc.jsonl work/aozora.jsonl work/livedoor.jsonl work/wikipedia.jsonl work/wikipedia_head.jsonl
YAHOO_APP_ID=... python3 -I read-yahoo.py work/yahoo.cache.jsonl work/kwdlc.jsonl work/livedoor.jsonl work/aozora.jsonl work/wikipedia.jsonl work/wikipedia_head.jsonl
python3 -I score.py work
python3 -I sheet.py work work kwdlc:150 aozora:150 livedoor:200 wikipedia:200
python3 -I tally.py ../../reports/2026-11-yahoo-verdicts.tsv
```

`score.py` は見出し語の全体の数字まで出す。現代の語彙の文の数字は、`wikipedia_head.jsonl` の `modern` が真の行だけで同じ計算をして求めた。
