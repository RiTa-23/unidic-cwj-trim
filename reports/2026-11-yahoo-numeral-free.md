# 数字を含まない文での Yahoo API との比較（2026-11）

Yahoo! ふりがな API は漢数字に読みを返さない。4者比較（`reports/2026-10-four-way.md`。main には未マージで、`a5472d7` にある）は、その文を却下に数えていた。
そこで、数字を含まない文だけで、本番構成と Yahoo を測り直した。

結果として、本番構成は全文の読みで Yahoo をわずかに上回る可能性が高いが、はっきり上回るとは言えない。辞書だけの構成は Yahoo より有意に低い。固有名詞の多い見出し語では Yahoo が上だった。

## 比べた構成

| 構成 | 中身 |
|---|---|
| 本番構成 | v3.2 辞書（`f4775d17…`）＋ Release `unidic-cwj-trim-v4` の user-lex。HENGE の読み Worker と同じ `readingOf` で組み立てる |
| 辞書のみ | v3.2 辞書。user-lex を重ねない |
| Yahoo | Yahoo! ふりがな API V2（`grade=1`）に1文ずつ送る。計測は 2026-11-06 |

## 文の選び方

コーパスの共通条件は `eval/yahoo-compare/common.py` にある。かな・漢字・句読点・「」だけからなり、漢字を含む8〜200字の文を採った。

数字は広めに除いた。算用数字は文字の条件で落ち、漢数字（一〜九、十、百、千、万、億、兆など）は語の一部でも文ごと落とした。「一緒」「千葉」のような語を含む文も入っていないので、これらの語の読みは今回の数字に表れない。

| コーパス | 候補の文 | 使った文 | 正解の読み |
|---|---|---|---|
| KWDLC（`c6ae49d`） | 10,156 | 10,156（全部） | 人手の形態素情報 |
| 青空文庫（国立国会図書館の振り仮名注釈コーパス） | 901,404 | 10,000 | 点字データから作った振り仮名 |
| livedoor ニュース（`ldcc-20140209`） | 63,274 | 10,000 | なし |
| Wikipedia 本文（2026-11-01 更新のダンプ、分割1・4） | 498,054 | 10,000 | なし |
| Wikipedia 見出し語（別枠） | 30,188 | 3,000 | 見出しの「漢字（よみ）」だけ |

- 青空文庫の振り仮名は点字に合わせて「は」を「わ」、「とうじ」を「とーじ」と書く。かな部分は本文の表記を使い、長音は両者に同じ変換をかけてそろえて採点した
- Wikipedia 本文は1ページ3文までとし、長い記事に偏らないようにした。テンプレートが抜けた行は文が欠けるので捨てた
- Wikipedia 見出し語は、読みが見出しの「よみ」から始まれば正解とした

Yahoo には重複を除いて 43,154文を送った。エラーが返った文は61で、「雍闓」「揷」のような珍しい漢字を含む文で確認した。

## 正解データとの比較

却下は、読みが返らないか、読みに漢字が残った文である。正解率は却下を不正解に数える。

| コーパス | 構成 | 正解率 | 誤読 | 却下 |
|---|---|---|---|---|
| KWDLC | 本番構成 | 87.86% | 1,226 | 7 |
| | 辞書のみ | 83.66% | 1,652 | 7 |
| | Yahoo | 86.30% | 1,390 | 1 |
| 青空文庫 | 本番構成 | 67.74% | 3,051 | 175 |
| | 辞書のみ | 63.92% | 3,433 | 175 |
| | Yahoo | 66.33% | 3,328 | 39 |

| 比較 | KWDLC | 青空文庫 |
|---|---|---|
| 本番構成 − Yahoo | +1.56pt（+0.85〜+2.28） | +1.41pt（+0.47〜+2.34） |
| 辞書のみ − Yahoo | −2.64pt（−3.49〜−1.78） | −2.41pt（−3.54〜−1.20） |

括弧は文書単位のブートストラップによる95%信頼区間である。

どの構成も読みを返した文だけで比べても、本番構成と Yahoo の差は KWDLC が +1.60pt、青空文庫が +1.67pt で、向きは変わらない。この条件の文字誤り率は、KWDLC が本番構成 0.82%、Yahoo 0.97%、青空文庫が本番構成 2.87%、Yahoo 3.06% だった。

Wikipedia 見出し語の正解率は、本番構成 72.03%、辞書のみ 71.40%、Yahoo 75.73% だった。本番構成と Yahoo の差は −3.70pt（−5.23〜−2.10）で、却下は本番構成 71、Yahoo 14 だった。本番構成と Yahoo がともに外した見出し語は496ある。「株式会社」を読みに含めない見出しのように、正解データの揺れも混ざっている。

## 読みが割れた文の判定

両者の読みが同じ文は、正しくても誤りでも正解率の差に影響しない。そこで、どちらかが却下された文を除き、本番構成と Yahoo の読みが割れた文を無作為に抜いて判定した。正解データのないコーパスでも、この方法で差を推定できる。

判定者は Claude（Opus 5.5）1人である。文ごとに無作為に A/B を割り当て、コーパスも混ぜ、対応表と正解データは判定が終わるまで見なかった。1文に誤りが1か所でもあれば、その読みを誤りとした。文ごとの結果は `reports/2026-11-yahoo-verdicts.tsv` にある。

| コーパス | 割れた文 | 判定数 | 本番だけ正しい | Yahoo だけ正しい | どちらも可 | どちらも誤り | 全体での差（95%信頼区間） |
|---|---|---|---|---|---|---|---|
| KWDLC | 1,445 / 10,156 | 150 | 56 | 64 | 25 | 5 | −0.76pt（−2.75〜+1.23） |
| 青空文庫 | 2,947 / 10,000 | 150 | 64 | 45 | 12 | 29 | +3.73pt（−0.20〜+7.66） |
| livedoor | 1,282 / 10,000 | 200 | 93 | 78 | 19 | 10 | +0.96pt（−0.71〜+2.63） |
| Wikipedia 本文 | 2,668 / 10,000 | 200 | 75 | 70 | 18 | 37 | +0.67pt（−2.53〜+3.74） |

どのコーパスでも信頼区間が0をまたぐ。4コーパスの単純平均は +1.15pt（−0.24〜+2.55）で、これも0をまたぐ。

KWDLC は、正解データとの比較では本番構成が上で、判定では Yahoo が上だった。user-lex の調整に KWDLC を使った影響が考えられるが、原因は切り分けていない。

## 読み取れること

- **漢数字の指摘は正しかった。** KWDLC の Yahoo の却下は、4者比較の167文から今回は1文になった。ただし本番構成との差は残った（4者比較 2.0pt、今回 1.56pt）。文の条件が少し違うので、この2つは厳密には比べられない
- **優位の大部分は user-lex による。** 辞書のみは KWDLC と青空文庫で Yahoo より有意に低い
- **固有名詞では Yahoo が上だった。** 見出し語は地名や学校名が多い。本番構成は却下も多いが、却下は誤読を配信しないので安全側の失敗である
- **精度は同等と説明するのが実測に合う。** 全文の読みではやや優勢、固有名詞では劣勢で、判定では有意差が出なかった

### 判定で見えた誤りの傾向

- 本番構成の誤り: 複合語の連濁と接尾辞（想い出話→おもいではなし、〜時→とき、〜下→した）、語の選び違い（高原→たかはら、姫君→ひめくん）、固有名詞（秋山真之→まさゆき）
- Yahoo の誤り: 語の切り方と音訓（精神体→せいしんからだ、世界中→せかいちゅう、選手→せんて）、固有名詞（観自在寺→かんじざいてら）、独女→ひとりおんな

### 同じ語で毎回外すもの

4コーパスの本文で、例に挙げた語を含む文を数えた。

| 語 | 含む文 | 本番構成の誤読 | Yahoo の誤読 |
|---|---|---|---|
| お母さん→おははさん | 36 | 36 | 0 |
| お父さん→おちちさん | 31 | 31 | 0 |
| 姫君→ひめくん | 11 | 11 | 0 |
| お母様→おははさま | 6 | 6 | 0 |
| 独女→ひとりおんな | 74 | 0 | 74 |
| 世界中→せかいちゅう | 30 | 0 | 30 |

お母さん・お父さんは日常語で、本番構成はこの条件の文をすべて誤読した。短い文で確かめると、user-lex を重ねなくても お／母／さん に割れて同じ読みになるので、辞書の側で起きている。

## 注意点

- 判定は1人の判断で、人手の正解データとは性質が違う。判定数も150〜200文なので、信頼区間は広い。読みの癖からどちらの読みか推測できる場合もあり、完全なブラインドではない
- KWDLC は dev 側の半分を user-lex の調整に使っている（`reports/2026-10-kwdlc.md`）ので、本番構成に有利である。辞書のみの行が調整の影響の少ない比較になる
- 青空文庫、livedoor、Wikipedia を調整に使った記録は `reports/` にない。青空文庫の正解率の絶対値は、点字由来のノイズと古い文体の影響を受けていると考えられ、あてにならない
- Wikipedia はダンプ全体ではなく2分割分から採った
- Yahoo の結果は API 側の更新で変わりうる

## 再現

コーパスの文と読みの出力は、リポジトリに入れない（`eval/README.md`）。`reports/2026-11-yahoo-verdicts.tsv` には文の ID と判定だけを載せている。スクリプトは `eval/yahoo-compare/` にある。Python の証明書でエラーになるときは、`SSL_CERT_FILE` で CA バンドルを指定する。

```sh
cd eval/yahoo-compare
python3 -I extract-kwdlc.py /path/to/KWDLC . work/kwdlc.jsonl
python3 -I extract-aozora.py /path/to/aozora . work/aozora.jsonl          # aozora_dataset を x/ に展開した場所
python3 -I extract-livedoor.py /path/to/livedoor . work/livedoor.jsonl    # ldcc を x/ に展開した場所
python3 -I extract-wikipedia.py work/wikipedia.jsonl . p1.xml.bz2 p4.xml.bz2
HENGE_ROOT=/path/to/HENGE bun read-engine.ts /path/to/user-lex.csv work work/kwdlc.jsonl work/aozora.jsonl work/livedoor.jsonl work/wikipedia.jsonl work/wikipedia_head.jsonl
YAHOO_APP_ID=... python3 -I read-yahoo.py work/yahoo.cache.jsonl work/kwdlc.jsonl work/livedoor.jsonl work/aozora.jsonl work/wikipedia.jsonl work/wikipedia_head.jsonl
python3 -I score.py work
python3 -I sheet.py work work kwdlc:150 aozora:150 livedoor:200 wikipedia:200
python3 -I tally.py ../../reports/2026-11-yahoo-verdicts.tsv
```
